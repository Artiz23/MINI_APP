# MINI_APP — Worklet

Telegram Mini App на Go с интерфейсом HTML/CSS/JavaScript. Данные хранятся в `data/miniapp.json`, файлы и ZIP-архивы — в `data/files`.

## Конфигурация

Токен бота читается во время запуска из переменной окружения:

```dotenv
MINIAPP_BOT_TOKEN=токен_из_BotFather
```

На Debian файл `/root/miniapp/.env` подключается к systemd:

```ini
[Service]
EnvironmentFile=/root/miniapp/.env
```

После изменения `.env` пересборка не нужна, достаточно `systemctl restart orh3-miniapp`. Файл должен иметь права `600` и не должен попадать в Git или каталог `web`.

Остальная встроенная конфигурация находится в `internal/secrets/secrets.go`: `WebAppURL`, `ListenAddr`, `ForumChatID`, чаты обращений и `MainAdminIDs`. Telegram-чаты согласования, оплаты и сальдо настраиваются администратором в Mini App. Чаты согласования и оплаты обязаны отличаться.

## Основные возможности

- Заявки: «Мои / Все», фильтры открытых, находящихся в работе и закрытых; чужие заявки доступны операционисту только для чтения.
- Статусы: `Открыта → В работе → Успешно закрыта` или `Сделка не состоялась`. Для несостоявшейся сделки обязательна причина.
- Этапы: согласование → оплата → завершённая задача → закрытое обращение. Администратор может пропустить этап с обязательной причиной.
- Комментарий редактируется владельцем заявки или администратором, пока заявка находится в работе.
- Экономика сделки хранит продажу клиенту, комиссию контрагента, агента и комиссию агента в структурированном виде.
- Сальдо хранит журнал операций и канонический текущий баланс; контрагента с финансовой историей удалить нельзя.
- Согласование отправляет заявку и снимок сальдо одним сообщением в выбранную группу с inline-кнопками «Принять», «Отклонить», «Спор». Решение принимает администратор. Ошибку доставки можно повторить без создания дубликата.
- Оплата использует отдельную Telegram-группу. Доставка сообщения и фактическое выполнение оплаты являются разными статусами.
- Клиент с флажком «Выплачивается комиссия» создаёт одно автоматическое напоминание в «Отправке» после успешного закрытия заявки.
- Встречи содержат название, безопасную HTTP/HTTPS-ссылку и дату/время по Москве.
- В разделе курсов над шестью прежними источниками доступны три настраиваемых слота. «Курсы» находятся в нижней панели, Канбан остаётся в общем меню.
- Ежемесячный ZIP-снимок выбранных разделов создаётся вручную или по расписанию и появляется в «Документы → Прочее». Вложения включаются отдельной настройкой. Старые сохранённые комплекты заявок остаются доступными только для совместимости; создание новых отключено.
- Бухгалтерия и аналитика показывают заявки, успешность, оборот, фиксированные комиссии, активность и указанную сотрудниками прибыль отдельно по валютам. Прибыль вводится вручную в экономике заявки; отрицательное значение означает убыток.

## Сборка

Из корня проекта в PowerShell для Debian amd64:

```powershell
$env:CGO_ENABLED = "0"
$env:GOOS = "linux"
$env:GOARCH = "amd64"
go build -o MINI_APP/dist/linux/miniapp ./MINI_APP/cmd/miniapp
Copy-Item MINI_APP/web/app.js,MINI_APP/web/app.css,MINI_APP/web/index.html -Destination MINI_APP/dist/linux/web -Force
```

Готовый бинарник: `MINI_APP/dist/linux/miniapp`. Рядом на сервере должна находиться папка `web`; папку `data` при обновлении не заменять.

Windows-сборка: `powershell -File MINI_APP\build-windows.ps1`. Linux-скрипт: `bash MINI_APP/build-linux.sh`.

## Проверки

```powershell
node --check MINI_APP/web/app.js
go test ./... -timeout 60s
```

Браузерные тесты используют подставной API и Playwright:

```powershell
$env:NODE_PATH = 'C:\Users\arty\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules'
$env:BROWSER_EXECUTABLE = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
node --test MINI_APP/tests/archive-ui.test.cjs
```

Перед обновлением сервера резервировать всю `/root/miniapp/data`, затем загружать новый бинарник и актуальные `web/app.js`, `web/app.css`, `web/index.html`.
